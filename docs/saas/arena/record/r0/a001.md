**Architecture contract.** Think of converting one company's office into leased suites: authentication opens the building, membership grants a suite, resource policy grants rooms, and every delivery needs an authorized destination. The analogy breaks where one person belongs to several customers and permissions change immediately; identity and cached roles therefore cannot substitute for current membership.

Use modules for identity, tenancy, projects/tasks, collaboration, files/connectors, jobs/notifications, billing and AI. HTTP and socket handlers invoke the same use cases and policy functions; repositories own Prisma access. Shared schemas define DTOs, pagination, errors, permissions and event envelopes. Browser code never imports database models.

Global `User` links to unique provider+subject identities; verified email is metadata, not tenant authorization. `Membership(tenantId,userId,role,status)` carries owner/admin/member/guest permissions. Platform operator access is separate, exceptional and audited. Invites are hashed, expiring, single-use, tenant-bound and accepted by the intended verified identity. Preserve Google-only, invitation-based beta initially; repair OAuth state/PKCE, session renewal/revocation and CSRF protections before broadening access. Basic identity consent must be separate from optional connectors. Google's [scope guidance](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) classifies broad Drive access as restricted; prefer incremental `drive.file` where sufficient, with [verification requirements](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification) assessed before external use. One product OAuth app normally serves tenants. Real credentials and provider verification remain release prerequisites.

Every business row belongs to a tenant; projects contain sprints and tasks, with optional task sprint for backlog. Composite foreign keys enforce matching tenant/project parents and tenant memberships for assignments. Uniqueness becomes tenant-scoped, including settings keys, summary periods and daily updates. Reject client attempts to set ownership. Scoped repositories enforce resource visibility on lists, counts, nested relationships, imports and exports. Add PostgreSQL RLS as defense in depth using non-owner/non-BYPASSRLS runtime roles and transaction-local context; test through the actual pooler. Migration/operator roles are isolated. RLS does not authorize within-tenant sharing.

Apply the boundary everywhere:

- HTTP resolves actor and active membership from trusted session plus validated workspace selector; absent context fails closed.
- Socket rooms include tenant and authorized resource/user; authorize joins and actions, minimize events, evict connections on logout/removal/role changes. Start with one API replica; scale only after shared adapter, rate limits and polling affinity tests.
- Jobs contain tenant, actor/service capability, idempotency key and scheduling timezone. Workers recheck permissions/status, claim leased jobs atomically, retry with limits and expose failures. Transactional outbox connects committed changes to delivery; vendor side effects require deduplication or compensation, not an exactly-once promise.
- Private storage uses tenant-prefixed keys and authorized short-lived downloads; authorize upload intent before allocation, enforce byte quotas, validate content and quarantine as required. Connector grants are tenant/user scoped, encrypted with mandatory keys when enabled, revocable and audited.
- Search initially uses scoped PostgreSQL queries/full-text indexes. Cache keys, client queries, search results, AI sources and derived summaries include tenant and relevant visibility. No cross-tenant retrieval or shared content cache.

Billing uses a provider adapter, server-owned prices/entitlements and atomic usage/seat reservations. Verify webhook signatures against raw bodies before JSON parsing; persist unique receipts and processed state transactionally with effects/outbox. Handle duplicates, retries and reordered events by reconciliation; do not discard legitimate delayed delivery arbitrarily. Success redirects never grant access. Downgrade overages become explicit restricted states, never deletion.

AI is opt-in and disabled on the proposed free plan. Bound input/output, concurrency, retries and duration; reserve worst-case spend transactionally before calls and reconcile actual usage. Account for retries/uncertain outcomes conservatively. Provider alerts supplement application limits; they are not assumed hard caps. Validate outputs with bounded schemas, distinguish generation failure from employee impact, retain sources and require human review. Log usage metadata, not private prompts/tokens.

**Ordered work packages and gates.** Implementation follows approval of this plan; independent agents can own disjoint modules after shared contracts settle.

1. **Baseline — release owner + data owner.** Inventory live environments/customers, all tables/files/grants/jobs and actual provider configuration. Create isolated synthetic fixtures and a sanitized staging rehearsal. Capture backups and restore them into a clean environment. Establish pinned toolchain, frozen installs, working lint and meaningful CI before structural changes. No production scanners or destructive suites.
2. **Current defects — security/backend owners, UX owner in parallel.** Repair authorization/broadcast/revocation, OAuth/CSRF, escaped mail templates, production mail behavior, token encryption fallback, hierarchy/backlog, draft preservation and socket lifecycle. Triage dependency advisories by reachable path; patch without blind force upgrades. Core boots without optional integrations; test-only identities cannot enter production.
3. **Foundation — one schema/policy owner, one design owner.** Freeze tenant/project/role semantics and shared contracts; build reusable UI primitives concurrently. Serialize migrations, auth context and token changes. Feature teams then implement scoped repository/use-case slices against these contracts.
4. **Expand/backfill — data owner, independently reviewed.** Add nullable ownership columns and new entities without destructive drops. Explicitly map legacy records into an approved legacy workspace/project; never infer ownership from domains. Preserve IDs. Backfill restartably in bounded batches, recording counts, orphan checks and relationship reconciliation. Use compatible dual writes or a documented maintenance freeze; stop old writers/schedulers before enforcing constraints. Repair invalid ranges/hierarchies before CHECK/FK/NOT NULL validation.
5. **Isolation cutover — backend + independent test owner.** Require tenant context for every transport, job, file, export, search and AI path. Validate scoped uniqueness/FKs/RLS and deny missing context. Two-tenant tests include overlapping humans, revoked memberships, forged IDs, nested reads, socket listeners, file links and worker retries. No second-customer access until these pass. UI onboarding/workspace switching ships against this boundary.
6. **Durability/provider transitions — platform/integration owners.** Replace process cron with durable jobs/outbox; migrate files using checksums and retained originals. Separately rehearse any PostgreSQL move to Neon: version/extensions, complete copy, write freeze or verified replication catch-up, final reconciliation, connection cutover and smoke tests. Never combine provider cutover with tenancy backfill. Keep source read-only during the recovery window; prohibit split writes.
7. **Commercial release — billing + operations owners.** Sandbox checkout, replay/reordering, concurrent quota use, failed payment/grace/downgrade tests; crash/retry and connector-outage tests; scoped staging DAST and capacity tests. CI requires build/types/lint, migration rebuild/upgrade, negative authorization, browser/socket journeys and scans. Independent reviewer checks evidence and diff scope before authorizing later commits/pushes; deployment remains separate. Verify protected branches and deploy only tested artifacts. Enable redacted structured logs, request/job IDs, dependency readiness, external alerting, spend alerts and incident ownership. Rehearse DB+object restore and rollback; document retention/export/deletion and obtain appropriate legal review before charging.

Rollback keeps additive schema compatible during the legacy-only window. After multiple tenants exist, **never restore an unscoped legacy binary**: disable the affected feature or roll forward. Database migration metadata commands do not undo data. A full restore requires an explicit recovery point and reconciliation of later writes/payments; external emails/shares need compensation. Retire legacy fields, source databases and old objects only after an agreed observation window and verified recovery.
