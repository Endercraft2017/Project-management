# Decision proposal: rebuild the SaaS boundaries, retain the working stack

Keep React/Vite, Express, TypeScript, Prisma and PostgreSQL. Restructure them into a modular monolith with one long-running API/Socket.IO process and a separately runnable durable worker. Use managed identity, private object storage and hosted checkout. Make tenant isolation and recoverability release gates before admitting a second customer organization.

**Assumptions and unresolved questions.** Customer/data status, seller jurisdiction, launch features, residency and operating budget are unknown. Preserve every existing record as potentially valuable; assume no authorization to deploy or migrate production. Treat “great free tier” as a development/pilot preference, with a capped paid budget required for commercial reliability. Default launch scope is workspaces, invitations, projects and tasks; retain chat, but make Drive/Sheets and AI optional. These assumptions avoid tying core availability to unavailable Google credentials. Proposed defaults below remain reviewable decisions.

- **Future SaaS requirements:** the schema has global user roles and no tenant, membership, project, billing or usage boundary. This proves missing capability, not an existing cross-tenant incident.

These are prior local results, not deployment assurance. Real OAuth, authenticated browser journeys, backup settings and production isolation remain unverified. This proposal changes no product files and makes no production calls.

**The architecture contract.** Use modules for identity, tenancy, projects/tasks, collaboration, files, integrations, billing, notifications and AI. HTTP, sockets and workers call the same application policies and use cases; controllers must not implement competing authorization rules. Shared Zod contracts define input, output, pagination, typed errors and events, with generated OpenAPI. Keep provider SDKs inside adapters. This sacrifices independent service scaling initially, while reducing deployment, consistency and operational complexity.

Identity is global: `User` plus provider subject/accounts. `Tenant` is the workspace, billing and security boundary. `Membership(tenantId,userId,role,status)` grants access; roles default to owner/admin/member. Separate platform administration from customer administration. Preserve existing task privacy until explicitly approved otherwise; tenant membership alone does not grant every task or conversation. Add project membership for private projects. Prevent removal of the last owner transactionally.

Every business record belongs to a tenant: projects, optional-sprint tasks, conversations, messages, files, notes, updates, summary periods, settings, connector grants and jobs. Global identity and provider-receipt tables are deliberate exceptions. Composite foreign keys enforce matching tenant/project ancestry and tenant membership for assignees; uniqueness includes tenant where appropriate. Hierarchy changes require cycle/depth checks, descendant updates and concurrency control. Add task versions for conflict detection.

Resolve workspace from an explicit request path, then verify active membership. Never infer it from email domain or trust a browser tenant ID. Avoid a mutable session-wide “current tenant,” which breaks multiple tabs. Require tenant context in repositories, exports, imports, statistics and administration. Add PostgreSQL RLS as a second boundary before multi-customer release: non-owner runtime role without BYPASSRLS, transaction-local tenant context, fail-closed policies and pooled-connection tests. Keep migrations on a separate privileged connection; never give the browser a service-role key or direct database access.

Isolation extends beyond SQL:

- Authorize socket room joins and each sensitive event; namespace rooms by tenant and resource. Revalidate recipients before sensitive broadcasts. Logout, suspension and membership removal invalidate sessions, evict/disconnect existing sockets and deny subsequent events. Reconnect fetches authoritative state.
- Jobs carry tenant, actor/service authority and idempotency key; workers recheck permission and entitlement before acting. A narrowly privileged dispatcher can claim job envelopes, not arbitrarily read customer tables. Use leases, bounded retries, dead letters and a transactional outbox; external delivery is at-least-once, with provider deduplication/compensation where available.
- Files use private tenant-prefixed keys plus ownership metadata, upload-intent authorization, byte/type quotas, quarantine and short-lived signed downloads. A key prefix alone is insufficient. Cleanup abandoned uploads and back up objects separately.
- Start search with tenant-filtered PostgreSQL queries/full-text indexes; no separate search service. Include tenant, user and policy version in caches. Any later search/vector index must enforce the same resource permissions. AI reads only authorized tenant data, treats content as untrusted input, validates bounded outputs and cannot choose arbitrary tools or scopes.

**Selected service stack and its limits.** Prices/allowances below were checked against official excerpts on 2026-10-27; recheck before procurement. Commercial eligibility, geography, DPA and contract terms still require review.

| Need | Default and cost boundary |
|---|---|
| Runtime/frontend | Railway: serve built Vite assets and `/api`/Socket.IO from one origin; separate worker from the same release. [Pricing](https://railway.com/pricing): Free trial $5/30 days, then $1/month allowance; Hobby $5 minimum, Pro $20 minimum, usage beyond credits billed. Plan production on Pro pending measured usage/team needs. A minimum is not the total bill. |
| Database/identity/files | Supabase PostgreSQL + Auth + private Storage. [Free](https://supabase.com/pricing): 500 MB DB, 50,000 MAU, 1 GB files, 5 GB egress, inactivity pause after one week, no automatic backups. Pro starts $25/month with seven-day daily database backups. Use Free for isolated development/pilot; production needs verified recovery and sufficient paid capacity. |
| Email | Resend with one verified sender domain. [Free](https://resend.com/pricing): 3,000/month, 100/day. Queue and deduplicate mail; verify SPF/DKIM/DMARC and delivery callbacks. Upgrade before invitation/notification demand reaches the daily cap. |
| Billing | Paddle hosted checkout/portal, conditional on seller/product approval; [price](https://www.paddle.com/pricing) 5% + $0.50/checkout transaction. Its merchant-of-record model reduces tax operations but adds fees and dependency. Use Stripe if [seller eligibility](https://stripe.com/global) and tax ownership favor it; [regional processing/Billing fees](https://stripe.com/pricing) still apply. |
| Monitoring | Sentry scrubbed errors; [Developer](https://sentry.io/pricing/) is one user/limited quota. Upgrade for team access/volume. Start operational metrics in structured logs; analytics/replay remain optional pending privacy choices. |

Consolidating identity/database/files reduces vendor count but introduces Supabase coupling and storage/egress limits. Retain adapters and tested exports. Consider [R2](https://developers.cloudflare.com/r2/pricing/) only when object economics justify migration: Standard allowance includes 10 GB-month, 1M Class A and 10M Class B operations, with no egress charge; backups/operations still cost resources.

Keep Node processes: existing Express, Socket.IO and cron assumptions do not transfer unchanged to edge functions. Validate TLS, proxy trust, cookie/CSRF handling, DB region/latency, Prisma connection limits and pooling under the selected runtime. Keep one API replica initially; scale only after a shared Socket.IO adapter, distributed limits and polling affinity are verified. [Render Free](https://render.com/docs/free) sleeps after 15 idle minutes and its free PostgreSQL expires after 30 days; it cannot satisfy reliable reminders. [Vercel Hobby](https://vercel.com/docs/plans/hobby) is personal/noncommercial. Strict $0 therefore changes the recommendation to a limited pilot with explicit downtime/recovery limits and no paid-customer reliability promise.

**Identity and integrations.** Use Supabase Auth for verified email links and optional basic Google sign-in; the backend owns one opaque, PostgreSQL-backed application session. Use state/PKCE and server-side identity verification/exchange, rotate session IDs, set Secure/HttpOnly/SameSite cookies, enforce CSRF/origin checks and implement revocation. Keep provider tokens encrypted server-side. The browser never receives database privileges. Authentication proves a person; backend membership grants workspace access.

Keep Google Drive/Sheets as separately consented workspace/user connectors. One platform OAuth app normally serves customers. Prefer `drive.file` and Picker if feature testing proves sufficient; it cannot automatically read all legacy arbitrary files. Broad [`drive.readonly` is restricted](https://developers.google.com/workspace/drive/api/guides/api-specific-auth); [server access may require recurring independent assessment](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification). Use [incremental consent](https://developers.google.com/identity/protocols/oauth2/web-server#incrementalAuth), revocation and explicit connection ownership. Disabled connectors must not prevent core startup.

**Commercial controls.** Store tenant subscription, server-owned entitlements, usage reservations/ledger and unique webhook receipts. Verify raw-body webhook signatures, tolerate retries/out-of-order delivery and reconcile current provider state; checkout redirects do not grant access. Seat increases and storage/AI reservations must be atomic. Show grace/cancelled/over-limit states without silently deleting data.

Default AI off on Free; enabled plans get explicit per-tenant spend/token/concurrency caps and input/output bounds. Reserve estimated maximum cost before enqueue, reconcile actual usage, and stop new work at the cap. Set service budget alerts at 50/80/100%; provider budgets are not universally hard caps. Emergency stops should disable expensive capabilities before core reads. Measure API/worker RAM/CPU, DB size/connections, object egress and mail before approving an operating ceiling; $45/month in cited Pro minimums is only a starting floor, excluding additional usage, domains, backup storage, email and payment/AI charges.

**Global UI/UX contract.** Extend existing [semantic CSS tokens](/workspace/Project-management/client/src/index.css:12) and Radix/Tailwind rather than create another styling system. One owned package/catalog defines typography, spacing, radius, semantic status colors, motion, focus and density; shared Button/IconButton, Field, Dialog/Sheet, Table/Tree, Notice and loading/error/empty states cover every feature. Use Storybook as the reviewed component reference; restrict new raw interactive primitives outside approved wrappers.

Ship one responsive shell with visible workspace identity, workspace switcher, project context and persistent navigation. Onboarding is verify identity → create/join workspace → first project/task → invite teammate; wrong-account, expired/revoked invite and permission-denied states must be recoverable. Separate 401 from outage; preserve drafts until acknowledged and show conflict/retry states. Tenant switches cancel stale requests, clear sensitive caches and replace socket subscriptions. Target WCAG 2.2 AA with manual keyboard/screen-reader checks, reduced motion, light/dark contrast and 360/768/1440-width fixtures. Persist IANA timezones; distinguish date-only values from instants. This is a target, not a compliance claim.

**Ordered delivery, owners and gates.** Use separate module owners with one integration reviewer; parallelize only after contracts agree. No implementation, commit or push is authorized by this proposal.

1. **Baseline — integration/security owner.** Inventory all tables, endpoints, events, files and side effects; confirm live-data status and feature scope. Fix reproducible lint/toolchain issues and unsafe startup coupling. Establish disposable test PostgreSQL and provider fakes confined to tests; no deployed authentication bypass.
2. **Current repairs — security and domain owners in parallel.** Remove mention/ID authorization bypasses, global broadcasts and stale socket access; repair backlog/hierarchy, range constraints, draft loss and output escaping. Each fix needs a failing behavioral regression first. Design owner can establish tokens/components concurrently.
3. **Expand/backfill — data owner, then independent review.** Add nullable tenancy/project columns and membership tables; preserve original IDs. Map records and existing connector grants to an explicit legacy workspace/project only after ownership review; never group customers by email domain. Measure invalid/orphan rows, propose repairs, dry-run on an isolated restored copy, then use restartable bounded batches, checkpoints and count/checksum reconciliation. Deploy compatible tenant-aware writes before completion; constrain any temporary legacy fallback to the legacy cohort. Validate composite FKs/CHECKs/indexes before NOT NULL; plan lock budgets and abort criteria.
4. **Cutover — integration/security owner.** Require tenant context across every transport, enable/test RLS and reject unscoped paths. Pass two-tenant isolation gates before enabling another workspace. Move managed identity in a separate release with reauthentication and verified account linking; preserve user IDs and never silently merge accounts by unverified email. Move DB hosting separately after tenancy stabilizes; rehearse final-write pause, synchronization and restore.
5. **Product/reliability — frontend and platform owners in parallel.** Integrate workspace onboarding/navigation against approved contracts. Replace cron/local files with durable jobs/private storage, import preview/batches, mail delivery states, audit events and monitoring. Copy objects, verify hashes/ownership, switch reads, retain originals through the rollback window.
6. **Commercial release — billing/platform owner and reviewer.** Sandbox checkout/webhooks, entitlements, spend limits, privacy/export/deletion/retention workflows and support runbooks. Rehearse restore, upstream outages and staging release; obtain budget/provider/launch decisions before production changes.

At every phase preserve additive compatibility and a documented rollback boundary. Before cutover, rollback compatible binaries and resume/reverse recorded batches safely. After another tenant exists, **never restore the unscoped legacy binary**: disable affected writes/features or roll forward. Whole-database restore requires explicit reconciliation of newer writes and external charges/emails; SQL rollback cannot undo external effects. Drop legacy fields/objects only after an agreed observation window and successful restore drill.

**Evidence required from implementers.** CI must run frozen-lockfile install, typecheck/build, repaired lint, contract tests and real-PostgreSQL migration/isolation tests. Include two tenants, one user in both, revocation, guessed IDs, nested records, files, exports/search, jobs and sockets; prove forbidden reads and writes fail. Exercise RLS after pooled-connection reuse, concurrent seats/spend, duplicate webhooks, worker death, DST schedules and restore counts. Playwright covers onboarding/task/billing journeys and [`axe`](https://playwright.dev/docs/accessibility-testing); [Storybook accessibility checks](https://storybook.js.org/docs/writing-tests/accessibility-testing) and representative visual states must fail CI when required assertions fail. Use redacted Gitleaks, npm advisory reachability review, [Semgrep CE](https://semgrep.dev/docs/licensing) and local/staging [ZAP baseline](https://www.zaproxy.org/docs/docker/baseline-scan/); [CodeQL](https://docs.github.com/en/code-security/code-scanning/introduction-to-code-scanning/about-code-scanning-with-codeql) depends on repository licensing/plan. These tools are recommendations, not claimed completed scans. Reviewer approves diffs, regression evidence and migration risk before any later authorized commit/push.

**Accumulated owner decisions.** Confirm existing data/customer ownership and downtime tolerance; approve pilot versus paid operating ceiling and alert owner; confirm seller entity/markets for Paddle versus Stripe; approve managed identity and account recovery; select launch-critical chat/Drive/Sheets/AI; choose workspace/project visibility and role rules; set residency, retention, RPO/RTO, backup budget and legal-review owner; approve one representative task/settings design and plan quotas/prices. Recommended defaults are preservation-first migration, managed identity, private projects with preserved task permissions, optional connectors/AI and a paid capped beta. Strict zero budget, regulated data, enterprise SSO/custom domains, or materially larger realtime workload would require revisiting this design and procurement before implementation.
