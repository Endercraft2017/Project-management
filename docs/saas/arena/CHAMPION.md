# Decision proposal: rebuild the SaaS boundaries, retain the working stack

Keep React/Vite, Express, TypeScript, Prisma and PostgreSQL. Restructure them into a modular monolith with one long-running API/Socket.IO process and a separately runnable durable worker. Use managed identity, private object storage and hosted checkout. Make tenant isolation and recoverability release gates before admitting a second customer organization.

**Assumptions and unresolved questions.** Customer/data status, seller jurisdiction, residency and budget are unknown. Preserve existing records; production changes are unauthorized. Free tiers suit development/pilots; commercial reliability needs an approved paid ceiling. Default launch scope: workspaces, invitations, projects, tasks and retained chat; Drive/Sheets and AI are optional. Core availability must not depend on unavailable Google credentials.

**What the evidence establishes.** Reviewed HEAD `fb1a9c757e76d3414c8dbe66d888a9088c5ca2ce`, source files, the supplied handbook and independent audit reports. The handbook supplies questions; official vendor documentation supplies vendor constraints.

- **Current defects:** task reads accept caller-selected `viewMode=mention` as permission ([controller](../../../server/src/tasks/controller.ts#L64)); task payloads broadcast to all sockets ([service](../../../server/src/tasks/service.ts#L333)). The user route authorizes a different parameter from the handler ([route](../../../server/src/users/routes.ts#L35), [middleware](../../../server/src/auth/middleware.ts#L85)). Fix these before broader access.
- **Current correctness gaps:** backlog movement writes `sprintId=null` ([service](../../../server/src/sprints/service.ts#L195)) while the [schema](../../../server/prisma/schema.prisma#L94) requires it. Progress/depth comments are unsupported by CHECK constraints in [migrations](../../../server/prisma/migrations/20250111000000_init/migration.sql#L47). This corroborates the previously reported invalid-value test failures; their 30-pass/2-fail run was not rerun here.
- **Additional current blockers:** [invitations](../../../server/src/invites/service.ts#L46) reject existing global accounts; [public acceptance](../../../server/src/invites/routes.ts#L24) creates a user without verified-identity matching. [Reactions](../../../server/src/chat/message-service.ts#L386) rewrite JSON after a separate read, permitting concurrent lost updates. [Deployment YAML](../../../.github/workflows/deploy.yml#L3) runs on main pushes without validation dependencies and installs an unpinned CLI; live branch protections and deployment settings are unverified.
- **Future SaaS requirements:** the schema has global user roles and no tenant, membership, project, billing or usage boundary. This proves missing capability, not an existing cross-tenant incident.
- **Availability/UI defects:** [Google configuration](../../../server/src/config/index.ts#L21) and [AI construction](../../../server/src/services/openai.service.ts#L40) require optional-provider secrets; [server startup](../../../server/src/server.ts#L50) starts schedulers in every API instance. [App](../../../client/src/App.tsx#L239) treats connection errors as sign-in, and [chat input](../../../client/src/components/chat/MessageInput.tsx#L70) clears drafts before success.

Captured [build](../evidence/build.log), [frontend tests](../evidence/client-tests.log) and [lint](../evidence/lint.log) show successful build, 19 frontend passes and failing lint. These are prior local results, not deployment assurance. Real OAuth, authenticated browser journeys, backup settings and production isolation remain unverified. This proposal changes no product files and makes no production calls.

**The architecture contract.** Use modules for identity, tenancy, projects/tasks, collaboration, files, integrations, billing, notifications and AI. HTTP, sockets and workers call the same application policies and use cases; controllers must not implement competing authorization rules. Shared Zod contracts define input, output, pagination, typed errors and events, with generated OpenAPI. Keep provider SDKs inside adapters. This sacrifices independent service scaling initially, while reducing deployment, consistency and operational complexity.

Identity is global: `User` plus provider subject/accounts. `Tenant` is the workspace, billing and security boundary. `Membership` is unique on `(tenantId,userId)`, with role/status granting owner/admin/member access. Separate platform from customer administration; preserve task/conversation privacy and private-project membership. Prevent removing the last owner transactionally.

Replace global-account invitations with tenant-bound invitations containing intended normalized email, grantable role, inviter, hashed random token, expiry and status. Creation/resend/revocation require tenant authority; owners transfer ownership separately. Acceptance requires an authenticated identity whose server-verified email matches the invite; client profile fields and token possession alone grant nothing. New users verify identity first; existing users can join another workspace without another account or global-role changes. Atomically consume a pending, unexpired, unrevoked invitation and create membership/seat reservation under a uniqueness constraint; concurrent acceptance, revocation and retries cannot duplicate grants. Return recoverable wrong-account/expired/revoked states. Remove email-domain admission and OAuth callback auto-accept/global-role assignment; invitations never reactivate platform-suspended identities.

Every business record belongs to a tenant: projects, optional-sprint tasks, conversations, messages, files, notes, updates, summary periods, settings, connector grants and jobs. Global identity and provider-receipt tables are deliberate exceptions. Composite foreign keys enforce matching tenant/project ancestry and tenant membership for assignees; uniqueness includes tenant where appropriate. Hierarchy changes require cycle/depth checks, descendant updates and concurrency control. Add task versions. Normalize reactions as `MessageReaction(tenantId,messageId,userId,emoji)` with unique message/user/emoji and tenant-consistent foreign keys; authorized atomic insert/delete makes retries idempotent and preserves concurrent reactions.

Resolve workspace from an explicit request path, then verify active membership. Never infer it from email domain or trust a browser tenant ID. Avoid a mutable session-wide “current tenant,” which breaks multiple tabs. Require tenant context in repositories, exports, imports, statistics and administration. Add PostgreSQL RLS as a second boundary before multi-customer release: non-owner runtime role without BYPASSRLS, transaction-local tenant context, fail-closed policies and pooled-connection tests. Keep migrations on a separate privileged connection; never give the browser a service-role key or direct database access.

Isolation extends beyond SQL:

- Authorize socket room joins and each sensitive event; namespace rooms by tenant and resource. Revalidate recipients before sensitive broadcasts. Logout, suspension and membership removal invalidate sessions, evict/disconnect existing sockets and deny subsequent events. Reconnect fetches authoritative state.
- Jobs carry tenant, actor/service authority and idempotency key; workers recheck permission and entitlement before acting. A narrowly privileged dispatcher can claim job envelopes, not arbitrarily read customer tables. Use leases, bounded retries, dead letters and a transactional outbox; external delivery is at-least-once, with provider deduplication/compensation where available.
- Files use private tenant-prefixed keys plus ownership metadata, upload-intent authorization, byte/type quotas, quarantine and short-lived signed downloads. A key prefix alone is insufficient. Cleanup abandoned uploads and back up objects separately.
- Start search with tenant-filtered PostgreSQL queries/full-text indexes; no separate search service. Include tenant, user and policy version in caches. Any later search/vector index must enforce the same resource permissions. AI reads only authorized tenant data, treats content as untrusted input, validates bounded outputs and cannot choose arbitrary tools or scopes.

**Selected service stack and its limits.** Prices/allowances below were checked against official excerpts on 2026-10-27; recheck before procurement. Commercial eligibility, geography, DPA and contract terms still require review.

| Need | Default and cost boundary |
|---|---|

[Pricing](https://railway.com/pricing): Free trial $5/30 days, then $1/month allowance; Hobby $5 minimum, Pro $20 minimum, usage beyond credits billed. Plan production on Pro pending measured usage/team needs. A minimum is not the total bill. |
| Database/identity/files | Supabase PostgreSQL + Auth + private Storage. | Email | Resend with one verified sender domain. [Free](https://resend.com/pricing): 3,000/month, 100/day. Queue and deduplicate mail; verify SPF/DKIM/DMARC and delivery callbacks. Upgrade before invitation/notification demand reaches the daily cap. |
| Billing | Paddle hosted checkout/portal, conditional on seller/product approval; [price](https://www.paddle.com/pricing) 5% + $0.50/checkout transaction. Its merchant-of-record model reduces tax operations but adds fees and dependency. Consolidation reduces vendor count but adds coupling; retain adapters and tested exports. Consider [R2](https://developers.cloudflare.com/r2/pricing/) when storage economics justify migration: Standard includes 10 GB-month, 1M Class A/10M Class B operations and free egress; backups still require resources.

Keep Node processes: existing Express, Socket.IO and cron assumptions do not transfer unchanged to edge functions. Validate TLS, proxy trust, cookie/CSRF handling, DB region/latency, Prisma connection limits and pooling under the selected runtime. Keep one API replica initially; scale only after a shared Socket.IO adapter, distributed limits and polling affinity are verified. [Render Free](https://render.com/docs/free) sleeps after 15 idle minutes and its free PostgreSQL expires after 30 days; it cannot satisfy reliable reminders. [Vercel Hobby](https://vercel.com/docs/plans/hobby) is personal/noncommercial. Strict $0 therefore changes the recommendation to a limited pilot with explicit downtime/recovery limits and no paid-customer reliability promise.

**Identity and integrations.** Use Supabase Auth for verified email links and optional basic Google sign-in; the backend owns one opaque, PostgreSQL-backed application session. Use state/PKCE and server-side identity verification/exchange, rotate session IDs, set Secure/HttpOnly/SameSite cookies, enforce CSRF/origin checks and implement revocation. Keep provider tokens encrypted server-side. The browser never receives database privileges. Authentication proves a person; backend membership grants workspace access.

Keep Google Drive/Sheets as separately consented workspace/user connectors. One platform OAuth app normally serves customers. Prefer `drive.file` and Picker if feature testing proves sufficient; it cannot automatically read all legacy arbitrary files. Broad [`drive.readonly` is restricted](https://developers.google.com/workspace/drive/api/guides/api-specific-auth); [server access may require recurring independent assessment](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification). Use [incremental consent](https://developers.google.com/identity/protocols/oauth2/web-server#incrementalAuth), revocation and explicit connection ownership. Disabled connectors must not prevent core startup.

**Commercial controls.** Store tenant subscription, server-owned entitlements, usage reservations/ledger and unique webhook receipts. Verify raw-body webhook signatures, tolerate retries/out-of-order delivery and reconcile current provider state; checkout redirects do not grant access. Seat increases and storage/AI reservations must be atomic. Show grace/cancelled/over-limit states without silently deleting data.

Default AI off on Free; enabled plans get explicit per-tenant spend/token/concurrency caps and input/output bounds. Reserve estimated maximum cost before enqueue, reconcile actual usage, and stop new work at the cap. Set service budget alerts at 50/80/100%; provider budgets are not universally hard caps. Emergency stops should disable expensive capabilities before core reads. Measure API/worker RAM/CPU, DB size/connections, object egress and mail before approving an operating ceiling; $45/month in cited Pro minimums is only a starting floor, excluding additional usage, domains, backup storage, email and payment/AI charges.

**Global UI/UX contract.** Extend existing [semantic CSS tokens](../../../client/src/index.css#L12) and Radix/Tailwind rather than create another styling system. One owned package/catalog defines typography, spacing, radius, semantic status colors, motion, focus and density; shared Button/IconButton, Field, Dialog/Sheet, Table/Tree, Notice and loading/error/empty states cover every feature. Use Storybook as the reviewed component reference; restrict new raw interactive primitives outside approved wrappers.

Ship one responsive shell with visible workspace identity, workspace switcher, project context and persistent navigation. Onboarding is verify identity → create/join workspace → first project/task → invite teammate; wrong-account, expired/revoked invite and permission-denied states must be recoverable. Separate 401 from outage; preserve drafts until acknowledged and show conflict/retry states. Tenant switches cancel stale requests, clear sensitive caches and replace socket subscriptions. Target WCAG 2.2 AA with manual keyboard/screen-reader checks, reduced motion, light/dark contrast and 360/768/1440-width fixtures. Persist IANA timezones; distinguish date-only values from instants. This is a target, not a compliance claim.

**Ordered delivery, owners and gates.** Use separate module owners with one integration reviewer; parallelize only after contracts agree. No implementation, commit or push is authorized by this proposal.

1. **Baseline — integration/security owner.** Inventory data, endpoints, events, files, side effects and release triggers; confirm live-data/scope. Repair lint/startup coupling and align pinned Node/npm plus `npm ci`. Establish disposable PostgreSQL/provider fakes confined to tests. Replace the unchecked deployment path with the enforced gates below before further releases.
2. **Current repairs — security/domain owners in parallel.** Remove authorization bypasses/global broadcasts/stale socket access; repair backlog/hierarchy, constraints, draft loss and escaping. Normalize/backfill current reaction JSON by message/user/emoji with reconciliation and concurrent two-user add/remove/retry regressions; phase 3 adds tenant keys. Each defect needs a failing behavioral regression. Design tokens/components proceed concurrently.
3. **Expand/backfill — data owner, then independent review.** Add nullable tenancy/project columns, membership and tenant-invitation tables; preserve original IDs. Map records and existing connector grants to an explicit legacy workspace/project only after ownership review; never group customers by email domain. Measure invalid/orphan rows, propose repairs, dry-run on an isolated restored copy, then use restartable bounded batches, checkpoints and count/checksum reconciliation. Deploy compatible tenant-aware writes before completion; constrain any temporary legacy fallback to the legacy cohort. Validate composite FKs/CHECKs/indexes before NOT NULL; plan lock budgets and abort criteria.
4. **Cutover — integration/security owner.** Require tenant context across every transport, enable/test RLS and reject unscoped paths. Pass two-tenant isolation gates before enabling another workspace. Move managed identity and invitation acceptance together in a separate release; preserve IDs, require reauthentication/verified linking, retire global invite paths and revoke/reissue legacy pending invites. Test new/existing identities joining workspace B, wrong-account rejection, expiry, replay and concurrent revocation; never merge accounts by unverified email. Move DB hosting separately after tenancy stabilizes; rehearse final-write pause, synchronization and restore.
5. **Product/reliability — frontend and platform owners in parallel.** Integrate workspace onboarding/navigation against approved contracts. Replace cron/local files with durable jobs/private storage, import preview/batches, mail delivery states, audit events and monitoring. Copy objects, verify hashes/ownership, switch reads, retain originals through the rollback window.
6. **Commercial release — billing/platform owner and reviewer.** Sandbox checkout/webhooks, entitlements, spend limits, privacy/export/deletion/retention workflows and support runbooks. Rehearse restore, upstream outages and staging release; obtain budget/provider/launch decisions before production changes.

Migrations run once through a locked privileged release job, separate from API startup ([current startup migrates](../../../railway.json#L9)). At every phase preserve additive compatibility and a documented rollback boundary. Before cutover, rollback compatible binaries and resume/reverse recorded batches safely. After another tenant exists, **never restore the unscoped legacy binary**: disable affected writes/features or roll forward. Whole-database restore requires explicit reconciliation of newer writes and external charges/emails; SQL rollback cannot undo external effects. Drop legacy fields/objects only after an agreed observation window and successful restore drill.

**Enforced release gates and evidence.** Replace the current YAML with PR/main validation and deploy jobs whose `needs` requires successful validation of the exact commit. Build once, deploy its immutable artifact/digest after staging smoke checks and designated production review; pin actions/CLI, restrict deployment secrets/permissions and serialize migrations/releases. Require protected-main PR review and named status checks, block unchecked direct/bypass pushes, and inventory/disable alternative automatic deployment paths. Verify plan support and actual rules in GitHub/Railway; these controls are proposed, not established. CI requires frozen-lockfile install, typecheck/build, repaired lint, contract tests and real-PostgreSQL migration/isolation tests. Include two tenants, one user in both, revocation, guessed IDs, nested records, files, exports/search, jobs and sockets; prove forbidden reads and writes fail. Exercise RLS after pooled-connection reuse, concurrent seats/spend, duplicate webhooks, worker death, DST schedules and restore counts. Playwright covers onboarding/task/billing journeys and [`axe`](https://playwright.dev/docs/accessibility-testing); [Storybook accessibility checks](https://storybook.js.org/docs/writing-tests/accessibility-testing) and representative visual states must fail CI when required assertions fail. Use redacted Gitleaks, npm advisory reachability review, [Semgrep CE](https://semgrep.dev/docs/licensing) and local/staging [ZAP baseline](https://www.zaproxy.org/docs/docker/baseline-scan/); [CodeQL](https://docs.github.com/en/code-security/code-scanning/introduction-to-code-scanning/about-code-scanning-with-codeql) depends on repository licensing/plan. These tools are recommendations, not claimed completed scans. Integration reviewer approves diffs, regressions, isolation and migration/restore evidence before later authorized commits/pushes; release approval is a separate gate.

**Accumulated owner decisions.** Confirm existing data/customer ownership and downtime tolerance; approve pilot versus paid operating ceiling and alert owner; confirm seller entity/markets for Paddle versus Stripe; approve managed identity and account recovery; select launch-critical chat/Drive/Sheets/AI; choose workspace/project visibility and role rules; set residency, retention, RPO/RTO, backup budget and legal-review owner; approve one representative task/settings design and plan quotas/prices. Recommended defaults are preservation-first migration, managed identity, private projects with preserved task permissions, optional connectors/AI and a paid capped beta. Strict zero budget, regulated data, enterprise SSO/custom domains, or materially larger realtime workload would require revisiting this design and procurement before implementation.
