Checked 2026-10-27 against the linked official pages. Prices below are in the currencies and regions shown on the vendor pages, generally USD; taxes, exchange rates, provider approval and changing quotas remain separate. ## Architecture implication

A low-risk default is to retain the React/Vite + Express/Prisma/PostgreSQL workspace and rebuild its tenancy/security boundaries as a modular monolith. Existing Socket.IO connections and cron-in-process work assume a long-lived Node runtime. A wholesale move to edge/serverless functions or a second frontend framework has a real migration cost; it is not justified merely because a provider advertises a free allowance. Separate the HTTP/realtime process from a persistent, idempotent background worker before increasing API replicas. Define provider interfaces for identity, object storage, mail, billing and AI; deploy one selected implementation for each rather than running several interchangeable vendors at once.

The budget distinction matters: free tiers can support development and a low-traffic pilot, but sleeping app instances, paused databases, limited backup retention, email caps and absent SLAs do not constitute production reliability. Confirm an operating budget and verified reliability/restore controls before accepting paying customers; set ceilings/alerts and upgrade triggers even for usage-based products.

## Google login versus Drive connector: an important cost distinction

Google Sign-In's basic profile/email use is not a paid-per-login service. The current app also requests Drive access. [Drive's scope guide](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) classifies broad Drive scopes including `drive.readonly` as restricted. It states that storing restricted-scope data on servers or transmitting it requires a security assessment. [Google's restricted-scope verification requirements](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification) state server access to restricted-scope user data requires an approved independent third-party assessment at least every 12 months. Cost and time are not specified as a universal fixed amount, and exceptions/actual deployment applicability need verification.

Recommendation: separate basic account login (`openid`, profile, email) from an explicitly optional Google Drive/Sheets connector. Ask for additional access only when the user connects that feature, following [incremental authorization](https://developers.google.com/identity/protocols/oauth2/web-server#incrementalAuth). Prefer non-sensitive `drive.file` with Google Picker and per-file access when it meets actual feature requirements; this has narrower permission and simpler verification. It does not magically grant access to all arbitrary legacy file IDs. Confirm existing file-selection, preview, import, and Sheet sync behavior against the narrower scope before migrating. Keep refresh tokens encrypted, revoke/disconnect cleanly, and define tenant ownership versus user grants. Do not call the current broad-Drive workflow cost-free just because basic Google login is free.

## Free plans that should not be oversold

- [Vercel Hobby](https://vercel.com/docs/plans/hobby) explicitly restricts use to non-commercial personal projects. It is not the free commercial SaaS recommendation. A paid Vercel plan would be a distinct budget choice, and moving this app to Vercel Functions still requires realtime/worker design.
- Render Free is useful for pilot HTTP/WebSocket validation, not a guarantee that scheduled jobs run while idle. Free Postgres expiration rules disqualify it as a lasting customer database.
- Railway's $1 recurring credit is an allowance, not an always-free full stack. Live-process state cannot be relied on after restarts, deployments or quota exhaustion.
- A database free-tier row does not establish backups, restore drills, data residency, uptime promises or legal compliance. These must become release evidence and budget gates.
- Publicly advertised no-signup/no-key OSS tooling can still consume coding-agent subscription/tokens/compute. An MIT skill being free does not make a 100-agent tournament free to run.
- None of the recommended services was found on the inspected pricing page to have Vercel-Hobby-style personal-only wording; this is not an exhaustive contract review. Verify final TOS/DPA, acceptable use, geography, subprocessor list, export/deletion, data transfer and commercial eligibility before procurement.

The full skill, `bracket.py`, rubric and strategy data were read before execution and SHA-256 digests retained in `.arena/vendor/provenance.json`. `bracket.py` uses Python standard-library JSON/local file bookkeeping only; no downloaded install script, network call, dynamic eval or external process execution was found. Fetching/reading a skill does not make it trusted over user/developer instructions.

Run configured as **2 independent same-model competitors, 1 round, 7 phase calls**, rather than the default 100 competitors/595 calls. Initial spawn waves were serialized; parent then authorized waves of two for attacks/defenses, giving five actual waves with phase barriers preserved. All competitors receive one identical standalone task plus differing strategy cards; each attacks the other, defends/revises, and an independent judge scores the written rubric. Orchestrator does not pick a winner. The written task includes the user's consistency/tenancy/security/UI/free-tier goals, known evidence and required caveats, without mandating an architectural outcome. This is a bounded decision exercise, not proof of correct architecture; parent audit/review remains the implementation gate.

The independent judge selected a002, **98.5–90** on the skill rubric. This is a two-proposal same-model comparison, not proof that all options were explored or a probability of architectural success. ## Decisions requiring owner input

1. Seller legal jurisdiction and buyer markets; Stripe eligibility versus merchant-of-record approach. Do not infer jurisdiction from Manila timezone.
2. Strict $0 pilot versus a capped monthly production budget; acceptable idle startup latency, backup retention, RPO/RTO and who receives spending alerts.
3. Managed identity versus self-hosted identity; email magic-link/password and optional Google login; whether enterprise SSO belongs in launch scope.
4. Are Google Drive/Sheets, AI summaries and chat launch requirements? Their scope, data processing, quota/cost and reliability implications differ from basic task management.
5. Existing production/customer data and migration downtime constraints; do not assume resettable data.
6. Data residency/privacy target markets and regulated-data exclusions; legal drafting/review ownership.
7. Exact branding/design direction can remain pending while shared tokens/component contracts and accessibility rules are established.
